영속성 전이(CASCADE) : 특정 엔티티를 영속 상태(persist)로 만들 때 연관된 엔티티도 함께 영속 상태로 만들고 싶을 떄 사용
-> 사람들이 대부분, 영속성 전이를 연관 관계, 즉시 로딩/지연 로딩과 관련된 것이라고 오해를 하는데, 전혀 관련이 없다. 
ex) 부모 엔티티를 저장(persist)할 때 자식 엔티티도 함께 자동으로 영속 상태로 만들고 싶을 떄!!!

영속성 전이를 사용해도 되는 2가지 조건
1. 오직 소유자 객체가 1개일 때
2. 소유자 객체와 피소유자 객체의 등록/변경/삭제의 라이프 사이클이 같을 때
※만약 A라는 자식 객체가 B라는 부모 객체 이외의 객체에서도 소유하고 있는 경우, 만약 부모 객체가 삭제되어 CASCADE 설정에 의해 자식 객체도 삭제되고 하는 경우, 다른 소유 객체 입장에서는 자기가 소유하고 있던 객체가 사라지므로
심각한 에러가 발생을 한다. 이는 운영 상 매우 치명적인 이유다.


고아 객체(Orphan Object) : 부모 엔티티와 연관 관계가 끊어진 자식 엔티티를 자동으로 삭제
ex)

orphanRemoval = true // 고아 객체 삭제 설정(orphanRemoval의 디폴트 값은 false이다)

Parent parent1 = em.find(Parent.class, parent.getId());
parent1.getChildren().remove(0); // 자식 객체 하나가 부모 객체에서 떨어짐! 이 순간 DELETE문이 실행이 되며 DB에서 Parent 테이블과 Child 테이블에서 해당 자식 관련된 레코드가 삭제가 된다.

또한 em.remove(parent1); 실행 시에도 자식 엔티티는 고아 객체가 되므로 이떄 부모 객체에 종속된 모든 고아 객체도 자동으로 DELETE문 실행이 된다.(cascade=CASCADETYPE.REMOVE,ALL)과 똑같이 동작한다.

CascadeType.REMOVE VS orphanRemoval = true
・CascadeType.REMOVE = 부모를 삭제할 때 자식도 삭제
・orphanRemoval = true = 부모와의 관계에서 떨어진 자식을 삭제(즉, 부모를 삭제하지 않아도, 즉 부모가 살아 있어도 부모와 관계가 끊어진 자식 엔티티가 있으면 삭제)
-> orpahnRemoval은 CasCadeType.REMOVE와 달리 부모 객체가 삭제되지 않아도 DELETE문이 동작하는 반면, CascadeType.REMOVE는 부모 엔티티가 반드시 삭제되어야만 자식 엔티티도 삭제가 된다.


고아 객체 기능을 사용해도 되는 2가지 조건
1. 오직 소유자 객체가 1개일 때
2. 소유자 객체와 피소유자 객체의 등록/변경/삭제의 라이프 사이클이 같을 때
-> 영속성 전이와 같다.

cascade=CASCADETYPE.ALL + orphanRemoval = true 조합의 이점
1. 소유자 엔티티(부모 엔티티) 하나만 가지고 피소유 엔티티를 자동 관리할 수가 있다.
2. 피소유 엔티티의 라이프 사이클(등록/삭제 사이클)을 소유자 엔티티(부모 엔티티) 하나만 가지고 제어할 수가 있다.
ex)
Child child1 = new Child();
Child child2 = new Child();

Parent parent = new Parent();
parent.addChild(child1);
parent.addChild(child2);

entityManager.persist(parent); // CASCADETYPE.ALL에 의해 부모 엔티티가 등록됨과 동시에 자동으로 자식 엔티티가 등록이 된다.
entityManager.remove(parent); // orphanRemoval=true에 의해 부모 엔티티가 삭제됨과 동시에 자동으로 자식 엔티티가 삭제가 된다.
-> 즉 자식 엔티티의 라이프 사이클을 지금 부모 엔티티 하나만으로 완벽히 제어하고 있다.
※이 방법은 DDD 설계에서 Aggregate root를 구현할 때 유용하게 사용한다고 한다.....
